Fix plan

The phases are ordered so each one makes the next one measurable. There's no point tuning the model while the site is offline half the day, or while the teams it predicts have no history.

Phase 0: stop the bleeding (about 1 day)

Log: Phase 0 decisions, changes, commands and deploy steps. Deployed and verified on production 30 Sep 2026.

  • Run the verification commands. Delete stray NAT gateways and unattached EIPs. Add an AWS Budget alert (COST-04).
  • ECR lifecycle (keep 5 images), 14-day log retention, apps logger → INFO (COST-05, COST-06).
  • Raise the anonymous read throttle, add a strict scope for AI/generate, remove 15-second live polling, and load AI analysis on click only (API-01).
  • Lock down DocumentViewSet, generate/batch and AI generate. Set an OpenRouter spend limit. Remove --clear from admin args (SEC-01, SEC-03).
  • Admin buttons: Sync → --fixtures-only; hide Train until the promotion check exists (Admin page, ML-04).
  • Replace the Help page's accuracy claims with the real measured figure and the baseline.

Done when: a dashboard tab can stay open for 2 hours without a 429; the AI endpoints reject anonymous floods; the AWS console shows at most one NAT and no orphaned EIPs.

Phase 1: available 24/7 and cheaper (about 3–5 days)

Log: Phase 1 decisions, changes, commands and runbook. Done 30 Sep 2026: app on Neon outside the VPC; NAT, VPC and RDS removed (final snapshot kept).

  • Pick Option A or B. For A: create the Neon/Supabase database, pg_dump → restore, remove VpcConfig, NAT, EIP, infra toggle and RDS (after a final snapshot).
  • A slim requirements-lambda.txt without torch, transformers, Celery or Redis.
  • Async AI analysis (a pending row + the manage Lambda + UI polling), or a Function URL (API-04).
  • DB connect_timeout, and a health check that tests the database.

Done when: the site loads at 22:00 UTC; the monthly estimate is under your target; an AI analysis completes end to end without a 504.

Phase 2: correct data (about 1 week)

Log: Phase 2 decisions, results and commands. Live 6 Oct 2026.

  • A TeamAlias table, a per-league mapping, and a one-off merge of duplicate teams (DATA-01).
  • A season helper; remove every hard-coded season (DATA-03, ML-09).
  • A twice-weekly current-season CSV sync for all 20 leagues (results, shots, odds); football-data.org for kickoff times and crests; re-sync stale "scheduled" matches (DATA-02, DATA-04).
  • Odds for upcoming fixtures (football-data.co.uk fixtures.csv or an odds API) (ML-01).
  • A timezone-aware kickoff_at, formatted in the browser using the Timezone setting (DATA-06).
  • League emblems and team crests after the merge (DATA-08).

Done when: no two Team rows share a club; all 20 leagues show this week's fixtures and last weekend's results; kickoff times match the official schedule in the user's timezone.

Phase 3: rebuild the model properly (about 2 weeks)

Log: Phase 3 scoreboard, decisions and commands. Live 6 Oct 2026: 50.3% accuracy on unseen matches (old model's real record 39.5%), log loss below the bookmakers.

  • Delete train_from_export and the "latest directory" fallback (ML-05).
  • Point-in-time features only: season-to-date, Elo, rolling shots and shots on target, xG where available; NaN for unknown (ML-02, ML-07).
  • A time-based train / calibration / test split; walk-forward evaluation; log loss, Brier, RPS and a calibration curve vs the bookmaker baseline (ML-03).
  • A promotion check before activation; weekly retraining (ML-04, COST-07).
  • A Dixon–Coles goals model for score, over/under 2.5 and both-teams-to-score (ML-08).
  • Save the model version and features_json; freeze predictions at kickoff; exclude back-tests from accuracy; one shared set of confidence bands (ML-11, ML-12, ML-14).

Done when: the test-season log loss is at or below the bookmaker-implied log loss, and accuracy is published next to the baseline and sample size.

Phase 4: frontend polish (about 1 week, can run alongside Phases 2–3)

  • Colour tokens as RGB channels, a brand DEFAULT, bg; fix every invented class name; add a lint rule (UI-01, UI-02).
  • Header: wire up or remove search, bell, user and ☰; replace the task pill with a TaskRun-based status (API-08).
  • Team page: the played field, home/away detection, next fixtures (API-10).
  • Predictions: server pagination, remove or implement the Value Bets filter, real predicted score (API-07).
  • Matches upcoming: day headers and a league filter. Match page: link team names.
  • Favourites: use useFavoritesStore, add ☆ buttons on team and league pages, remove the demo data.
  • Default View: redirect only on first load of a session.
  • Light theme pass; logo, favicon and OG image; accessibility labels; responsive Help page (UI-03, UI-04, UI-07, UI-08).

Done when: every row on the frontend page is marked Works, or has been removed on purpose.
