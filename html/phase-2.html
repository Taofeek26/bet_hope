Phase 2: correct data

The model can only be as good as its inputs. This phase makes each club one team, brings in the current season for all 20 leagues, adds bookmaker odds for upcoming fixtures, and stores kickoff times unambiguously.

Decisions

P2-D1A club is one team per country, not per league
Why
On real data the audit's duplicate problem was bigger than expected. Besides the 153 football-data.org duplicates, the CSV import made a new team every time a club was promoted or relegated (get_or_create(fd_name, league)), splitting 181 clubs. A newly promoted club started with zero history, which matters for the model.
How
TeamAlias (country + normalized name → team) and TeamResolver, used by every provider. Lookup order: exact spelling → alias → known hard cases (KNOWN_ALIASES) → unique token match → otherwise create and log. Exact spelling comes first because normalizing makes "Wimbledon" and "AFC Wimbledon" (different clubs) look alike. Team.league now means the division the club plays in now.
P2-D2Merge without throwing anything away
Why
The old cleanup_duplicate_teams deleted one of two rows for the same match, along with its odds, stats and predictions. It's deleted.
How
merge_duplicate_teams (dry run unless --apply) moves every match and every table that references the team, merges twin match rows field by field, keeps odds, stats and predictions, and records old names as aliases. I reviewed all 145 football-data.org pairings by eye before running it (all correct, e.g. "Club Atlético de Madrid → Ath Madrid", "Lincoln City FC → Lincoln").
P2-D3The current season for every league, twice a week
How
sync_real_data --current-season re-downloads this season's CSV for all 20 leagues (results, shots, odds). It's scheduled Mon and Thu 03:30 UTC (CurrentSeasonSyncSchedule), 20 small files taking about 4 minutes. The daily sync now also reads football-data.co.uk's fixtures file (with odds) and re-checks every match past its date that's still "scheduled", up to 60 days back.
P2-D4Seasons from the date
How
apps/core/seasons.py (unit-tested, including the 1999-00 / 2000-01 boundary) replaces every hard-coded season list. The CSV provider's season list, training defaults, settings and tasks are all computed now.
P2-D5Kickoff as one UTC instant
How
New Match.kickoff_at, with a migration that backfills existing rows: football-data.org times are already UTC, CSV times are converted from Europe/London. The API returns it, and the frontend shows it via formatKickoff() in the timezone from Settings, in all 6 places that showed a time. The Matches page's upcoming list now shows the date as well as the time.
