Design: colours, logos, typography

The visual system (near-black surfaces, a sky-blue accent, "blueprint" corner brackets) is coherent. Much of it doesn't render, though, because the class names in the pages don't match the colours defined in tailwind.config.js.

Source: frontend/tailwind.config.js, src/styles/globals.css, components and pages

Findings

UI-01HighBrand colour classes used across the app don't exist
Why
Tailwind defines brand only as brand-1, brand-2 and brand-3 (no DEFAULT) and has no bg colour. globals.css hand-defines only .text-brand and .border-brand. Every other variant is silently dropped at build time:
bg-brand, bg-brand/5, /10, /15, /20, /70, text-brand/70, /80, border-brand/20, /30, /40, /50, from-brand/10, to-brand/5, text-bg, bg-bg, bg-brand1, text-text-sec, text-text-primary, bg-card-hover, bg-surface-alt
Effect
Selected date pills (Dashboard, Predictions, Value Bets) lose their highlight. Team-initial avatar circles have no background. Value-bet "strong/good" cards look identical. The AI button gradient is missing. The mobile "has prediction" dot is invisible.
Fix
In tailwind.config.js: brand: { DEFAULT: 'rgb(var(--brand1-rgb) / <alpha-value>)', 1: …, 2: …, 3: … }, bg: 'rgb(var(--page-rgb) / <alpha-value>)'. Replace the invented names (text-text-sec → text-text-secondary, text-text-primary → text-text, bg-card-hover → bg-input). Add a CI grep, or eslint-plugin-tailwindcss no-custom-classname, to catch unknown classes.
UI-02HighOpacity modifiers on CSS-variable colours are silently dropped, which leaves the header transparent
Why
Colours such as surface: 'var(--surface)' can't take Tailwind 3's /50-style opacity, so classes like bg-surface/50, bg-surface/30, bg-card/50, border-border/50, bg-text-muted/10, text-text-muted/50 and bg-background-secondary/80 are never generated.
Effect
The sticky header has no background, so content scrolls visibly underneath it. Several match-row and panel backgrounds and dividers disappear.
Fix
Store the tokens as RGB channels (--surface-rgb: 17 17 17;) and define the colours as 'rgb(var(--surface-rgb) / <alpha-value>)'. That single change fixes every /NN class.
UI-03MediumThe light theme has invisible text
Where
text-white is hard-coded in Header, DailyPicks, UpcomingMatches, LiveMatches and PredictionStats; bg-black/40 is used in Admin logs; .glass uses a dark rgba; ::selection sets its colour to white
Fix
Use text-text (the token) everywhere, then test each page in light mode.
UI-04MediumNo logo, favicon or app icon
Where
frontend/public/ contains only .gitkeep; there's no app/icon.*; notifications reference /favicon.ico (404); the header uses a "BH" text box; the sidebar uses gradient text
Fix
Design one mark (e.g. a ball inside a rising chart line, in #38BDF8) and export it as app/icon.svg, app/apple-icon.png (180 px), public/favicon.ico and an Open Graph image (1200×630). Use the same mark in the sidebar header and in notifications. Team crests and league logos are covered in DATA-08.
UI-05LowTwo component systems mixed, so headings appear twice
Where
The Dashboard wraps <UpcomingMatches/> and <PredictionStats/>, which use the older Card/CardHeader with primary-*/accent-* colours, inside new .card blocks that have their own header
Effect
"Upcoming Matches" and "Model Performance" headings appear twice, with a card nested inside a card.
Fix
Pick one card component (the blueprint style) and remove the other.
UI-06LowColour meaning is inconsistent
What
"Win" and "success" are brand blue, while "correct prediction" is green. The "HOT" badge is sky blue. Red is used both for "live" and for "loss" / "incorrect".
Fix
Keep blue as the brand and interaction colour only. Use green for correct/win, red for incorrect/loss, amber for live/pending, and slate for draw.
UI-07LowAccessibility
What
Icon-only buttons have no aria-label (menu, search, bell, user, chevrons, sidebar toggle). Muted text contrast is too low (see the palette table). Some correct/incorrect states are shown by border colour alone. The settings toggles are hidden checkboxes whose label has no visible focus style.
UI-08LowResponsive gaps
What
The Help page grids have no breakpoints. The dashboard date selector has 7 pills plus two chevrons, and on small phones it scrolls horizontally with no scroll affordance. On mobile the sidebar turns into a top tab strip, but the header's ☰ (which does nothing) is still shown.

Typography

Inter (UI) and JetBrains Mono (numbers in metric plates) are loaded with next/font, and font-sans on <body> correctly overrides the system stack in globals.css. Sizes are consistent: headings 1.6 rem, card titles 1.1 rem, body 13–15 px. No changes are needed beyond the contrast fix above.

A class is "not generated" when Tailwind 3.4 can't resolve it from tailwind.config.js and globals.css doesn't define it by hand. A production build plus a grep of the output CSS will confirm each one.
