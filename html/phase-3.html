Phase 3: a model you can trust

The prediction model was rebuilt so that it only learns from the past, is measured on matches it has never seen, goes live only when it's better, and states its confidence honestly.

Decisions

P3-D1Point-in-time features, built in one pass
What
apps/ml_pipeline/v2/features.py walks every match in date order. Each match's features use only the state before it, then the state is updated with its result. The features are: Elo ratings (home advantage, goal-margin weighted, starting lower for clubs first seen in lower divisions), last-5/10 form (points, goals, shots, shots on target, home/away split), season-to-date points and goal difference, rest days, the league's recent home-win rate, and normalized market probabilities with the overround.
Fixes
ML-02: v1's season stats included the match's own result and later matches. ML-07: unknown is NaN with has_odds / history counts, not 0. Building every feature for 92,508 matches takes about 9 s (v1 took ~3 minutes of database queries).
P3-D2Learn a correction to the market, not a replacement
Tested
Four approaches on the same split (scratch scripts eval_v2.py, eval_v2b.py): plain XGBoost with all features (log loss 1.0041), without odds (1.0167), a logistic model on market + Elo + form (1.0031), and XGBoost with the market's log-probabilities as its starting point (1.0032, chosen). It learns only where form, Elo and shots disagree with the odds, and it was the best or level in every league tier.
Fallback
A separate model without market features for fixtures that have no odds yet. The daily run switches a fixture to the odds model as soon as odds appear.
P3-D3Goals from Poisson models, so every number agrees
What
Home and away goal models (XGBoost count:poisson) give a scoreline grid, from which come over 2.5, both-teams-to-score, and the predicted score: the most likely score consistent with the predicted result. v1's "home = total × 0.55" could show "Away win, 1–1" (ML-08).
P3-D4Time-based evaluation and a promotion check
What
Train ≤ 2023-24, validation = 2024-25 (early stopping only), test = the previous season onward. The windows move forward automatically each season. A new model goes live only if its test log loss beats the active model's on the same window (or v1's self-reported figure). Otherwise it's saved as archived with the reason (ML-03, ML-04). The daily schedule stays; a bad day can't replace a good model.
P3-D5Traceable, frozen predictions and an honest record
What
Each prediction stores its real model version and the key inputs (features_json), and isn't overwritten after kickoff. /predictions/stats counts only predictions created before kickoff on matches with a result (ML-11, ML-12). --historical back-filling is refused with v2, because it would be in-sample. Models are saved in XGBoost's own JSON format, which survives library upgrades.
