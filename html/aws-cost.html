AWS cost: where the money goes and how to cut it

Most of the bill pays for keeping a VPC reachable (NAT Gateway), a database that is off half the day anyway, and a container image several times bigger than it needs to be. The cheapest fix also fixes the biggest product problem: the site being offline every evening.

Source: infrastructure/template.yaml, .github/workflows/deploy-lambda-web.yml, backend/Dockerfile.lambda-web, backend/requirements.txt, backend/config/settings/*. Prices are us-east-1 list prices. Check them against your bill using the commands at the bottom.

Findings

COST-01HighThe NAT Gateway exists only because the Lambdas are inside the VPC
Where
template.yaml: WebFunction / ManageFunction VpcConfig, InfraToggleFunction
Why
The Lambdas sit in private subnets to reach RDS. They also need the internet (football-data.org, OpenRouter, S3, AWS Lambda invoke), which requires a NAT Gateway, the single most expensive piece. The daily create/delete toggle roughly halves it, but adds complexity and the downtime in COST-02.
Fix
Run the Lambdas outside the VPC and use a database that is reachable over TLS (Option A below), or move to one small server (Option B). Either way the NAT, EIP, VPC and toggle function disappear.
COST-02CriticalThe cost-saving schedule takes the whole site offline for 12 hours a day
Where
InfraStopSchedule cron(0 16 * * ? *) / InfraStartSchedule cron(0 4 * * ? *)
Effect
From 16:00 to 04:00 UTC (5pm–5am WAT) RDS is stopped. Every API call fails and every page shows its error state. That window covers most evening kick-offs in Europe and all of South America.
Also
RDS can take 5–10 minutes to become available after start, and the NAT waiter can take up to about 7 minutes. The fixture sync fires at 04:15, so on a slow morning it runs before the database is up and that day's results are skipped.
Fix
Remove the need for the toggle (Options A/B). Until then, run the first job at 04:30 or later and have it retry on a connection error.
COST-03HighRequests made while the database is stopped probably hang until the 29-second timeout, and you pay for every second
Where
No connect_timeout in DATABASES (base.py); frontend polling in frontend/src/hooks/useApi.ts
Effect
With the database stopped, each database-backed request likely waits for the TCP connect to time out, which is longer than the 29-second Lambda timeout. A browser tab left open overnight keeps polling every 15–60 seconds, and React Query retries once, so each failed call is billed for about 29 GB-seconds. Throttling caps this at roughly 100 slow calls per hour per visitor, which works out to about $0.5–2 per open tab per night. Likely: confirm in CloudWatch by looking for web Lambda durations near 29,000 ms between 16:00 and 04:00 UTC.
Fix
Add 'OPTIONS': {'connect_timeout': 5} to the database settings, stop polling after errors, remove the 15-second "live" polling (nothing updates live scores, see DATA-05), and make the site available 24/7.
COST-04HighThe infra toggle can leave a second NAT Gateway or orphaned Elastic IPs running
Where
InfraToggleFunction inline code: start() / stop()
Why
start() always allocates a new EIP and creates a new NAT without checking whether one already exists. stop() only deletes NATs in state available, and releases EIPs only after the delete waiter succeeds (40 × 10 s = 400 s, inside a 600 s timeout that also stops RDS). If stop() fails or times out even once, the old NAT runs through the night. The next morning a second NAT is created alongside it, and orphaned EIPs cost $3.60/month each.
Fix
Run the verification commands below today. In the function, make start/stop idempotent: reuse an existing NAT, delete NATs in pending state too, and release all EIPs tagged with NAT_NAME_TAG. Add an AWS Budgets alert (the first two budgets are free).
COST-05HighThe container image carries several GB of unused ML libraries, with no ECR lifecycle policy
Where
backend/requirements.txt, Dockerfile.lambda-web, deploy-lambda-web.yml
Why
The image installs torch, sentence-transformers, transformers, huggingface-hub, google-generativeai, celery, django-celery-beat/results, redis, django-redis, gunicorn, uvicorn, aiohttp and gcc. On Lambda there is no Celery broker, no Redis and no GPU, and local embeddings (torch) inside a 1 GB, 29-second web function aren't viable. Each push stores 2 tags. Old images are never deleted.
Effect
Growing ECR storage, slower cold starts (seconds on the first request after idle), and longer CI builds.
Fix
Split requirements into requirements-lambda.txt (Django, DRF, psycopg2-binary, numpy, pandas, scikit-learn, xgboost, joblib, boto3, openai, anthropic, apig-wsgi, whitenoise). Use API embeddings, or disable RAG. Add an ECR lifecycle rule keeping the last 5 images. Expect the image to drop from about 2–3 GB to about 0.5 GB (estimate).
COST-06MediumCloudWatch logs are kept forever and are verbose
Where
No AWS::Logs::LogGroup with RetentionInDays in the template; LOGGING['loggers']['apps']['level'] = 'DEBUG'
Fix
Declare the three log groups with 14-day retention and set the apps logger to INFO in production.
COST-07MediumRetraining every day costs compute and adds nothing on days without new results
Where
TrainModelSchedule cron(0 5 * * ? *)
Fix
Retrain weekly (e.g. Monday after the weekend's results) and only promote the new model if it beats the current one (see ML-04). Keep predictions refreshing daily.
COST-08LowThe static bucket is fully public and versioned, and appears unused
Where
StaticBucket + StaticBucketPolicy (Principal *)
Why
Static files are baked into the image by collectstatic and served by WhiteNoise. I found nothing that writes to this bucket. It is public-read with versioning and no clean-up rule.
Fix
Confirm it's empty, then remove the bucket and its policy from the template.
COST-09LowREST API instead of HTTP API or a Function URL
Why
REST APIs cost $3.50 per million requests against $1.00 for HTTP APIs, and both cap at about 29–30 seconds. A Lambda Function URL is free and allows up to 15 minutes, which would also fix the AI analysis timeout (API-04).

Verify against your account

Run these with the AWS CLI (region us-east-1). They are all read-only.

# 1. What you actually pay, by service, this month
aws ce get-cost-and-usage --time-period Start=2026-09-01,End=2026-09-30 \
  --granularity MONTHLY --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE

# 2. NAT gateways that exist right now (expect 0 after 16:00 UTC, 1 during the day)
aws ec2 describe-nat-gateways --filter Name=state,Values=pending,available \
  --query 'NatGateways[].[NatGatewayId,State,CreateTime]' --output table

# 3. Elastic IPs, including unattached ones (AssociationId empty = orphaned)
aws ec2 describe-addresses --query 'Addresses[].[PublicIp,AllocationId,AssociationId]' --output table

# 4. How many images ECR stores, and their total size in GB
aws ecr describe-images --repository-name bet-hope-web \
  --query 'length(imageDetails)'
aws ecr describe-images --repository-name bet-hope-web \
  --query 'sum(imageDetails[].imageSizeInBytes)' | awk '{print $1/1024/1024/1024 " GB"}'

# 5. Log groups: stored size and retention (null = forever)
aws logs describe-log-groups --log-group-name-prefix /aws/lambda/bet-hope \
  --query 'logGroups[].[logGroupName,storedBytes,retentionInDays]' --output table

# 6. Did web Lambda calls hang at ~29 s overnight? (max duration per hour, last 2 days)
aws cloudwatch get-metric-statistics --namespace AWS/Lambda --metric-name Duration \
  --dimensions Name=FunctionName,Value=bet-hope-web --statistics Maximum \
  --start-time $(date -u -v-2d +%Y-%m-%dT%H:%M:%SZ) --end-time $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --period 3600 --output table
Prices are public us-east-1 list prices at the time of writing and exclude tax and free-tier credits. The estimates assume the resources in template.yaml; anything created outside the template isn't included.
