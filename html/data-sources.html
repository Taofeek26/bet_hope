Data sources, league coverage and logos

The app says it covers 20 leagues. In practice, only 8 get new fixtures and results. The two providers name teams differently, which quietly splits one club into two database rows.

Findings

DATA-01CriticalTeam names don't match across providers, so duplicate teams get created
Where
football_data_org.py _find_or_create_team / _normalize_team_name; teams from CSVs are keyed by fd_name + league in football_data.py
Why
Name normalisation only strips suffixes like " fc"/" cf" and lower-cases, so short CSV names don't match full official names:
football-data.co.ukfootball-data.org (typical)
Man UnitedManchester United FC
Man CityManchester City FC
Nott'm ForestNottingham Forest FC
WolvesWolverhampton Wanderers FC
NewcastleNewcastle United FC
TottenhamTottenham Hotspur FC
Ath MadridClub Atlético de Madrid
Bayern MunichFC Bayern München
Paris SGParis Saint-Germain FC
InterFC Internazionale Milano
Every miss creates a new Team row with no match history. The normaliser also does plain substring replacement (' sc' → ''), which mangles names like "fc schalke 04" into "fchalke 04". That shows how fragile the matching is.
Effect
Features are empty for these teams (ML-06), standings split one club into two rows across sources, and team pages show only part of a club's history.
Fix
Add a TeamAlias(team, provider, name) table seeded with a mapping per league (about 20 teams per league). Look up by alias first, then fuzzy-match (e.g. rapidfuzz with a high threshold), and log unmatched names for a human to review. Then run a one-off merge of existing duplicates (the repo has cleanup_duplicate_teams; review it before running). For CL/EL, link each team to its domestic team instead of creating new rows.
DATA-02High12 of 20 leagues are frozen at the last manual import
Where
SyncDataSchedule uses --fixtures-only; football-data.org's free tier covers only 8 of the domestic leagues
Effect
These leagues show old standings and no upcoming matches, but the dashboard still says "AI-powered predictions across 20 major leagues worldwide".
Fix
Twice a week, download only the current season CSV for each of the 20 leagues from football-data.co.uk. That's 20 small files, well inside Lambda limits, and it brings results, shots and odds for every league. Keep football-data.org for fixture kickoff times and crests. Until then, label the frozen leagues "historical data only" in the UI.
DATA-03HighSeason codes are hard-coded
Where
settings.HISTORICAL_SEASONS / SEASON_DISPLAY (ends 2024-25), FootballDataProvider.SEASONS (starts at 2526, so no 2627), tasks/data_sync.py, train_model.py, Admin page train button (2425)
Fix
Derive the season from the date (the League.current_season property already does this per league) and use it everywhere.
DATA-04MediumResults older than 7 days are lost if a daily run fails
Where
sync_results_to_database(days=7); the job runs at 04:15, when the database may not be up yet (COST-02)
Effect
A match stays "scheduled" forever, its prediction is never checked, and standings are short a game.
Fix
Also re-sync any match whose kickoff has passed but whose status is still scheduled, however old. The CSV sync (DATA-02) back-fills these automatically too.
DATA-05MediumThere is no live-score source, but the UI polls for live matches every 15 seconds
Where
Status only changes during the once-a-day sync; useLiveMatches polls every 15 s; the dashboard, Matches page "Live" tab and notifications rely on it
Fix
Either add a real live source (e.g. football-data.org /matches?status=IN_PLAY every few minutes during match windows, within its rate limit), or remove the Live tab and polling and say so.
DATA-06MediumKickoff times are UTC but shown as if local
Where
football_data_org.py stores match_dt.time() from UTC; football-data.co.uk times are UK local time; the frontend prints kickoff_time as-is
Effect
In Lagos (WAT, UTC+1), every football-data.org kickoff looks one hour early. The Settings "Timezone" option has no effect (FE, Settings).
Fix
Store a single timezone-aware kickoff_at (UTC) and format it in the browser with formatTimeInZone (it already exists in lib/utils.ts).
DATA-07MediumTeam season stats and head-to-head tables are never filled
Where
Models TeamSeasonStats, HeadToHead; I found no sync code that writes them
Effect
The team page's stat tiles are hidden, the match page's head-to-head card never appears, and the season features are zero (ML-02). Standings still work because they fall back to computing from matches.
Fix
Compute both from Match rows on demand (with caching). There's no need to store them.
DATA-08MediumLogos: team crests for 8 leagues only, and no league logos
Where
Team.logo_url is set only from football-data.org crests; League.logo_url is never set
Effect
Every league card shows the same trophy icon. Teams in the other 12 leagues, and duplicate teams from DATA-01, show a letter circle whose background class doesn't exist (UI-01), so it renders as bare text.
Fix
Run the existing sync_teams_with_logos once after the team merge, and set League.logo_url from football-data.org competition emblems. For uncovered leagues, host a small crest set in S3 or frontend/public/crests/. Keep the letter fallback, but give it a working style.
