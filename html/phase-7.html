Phase 7: user accounts

Each user now has their own account. My bets, favourites and the weekly limit are stored on the server and follow them to any device, and the admin can see every user.

8 Oct 2026 · commits 1142535, frontend follow-ups · image 1142535… on both functions · migration accounts.0001

Before

Bets, favourites and settings were kept in each browser only (not shared between people), but nothing followed a user to another device and there was no list of users for the admin.

What was built

  • Sign-up / sign-in with email and password (Django users, hashed passwords, Django's password rules, sign-up limited to 10 an hour per address). JWT: 60-minute access token, refreshed automatically for 30 days. An expired session falls back to browsing signed out.
  • Per-user data (apps/accounts): UserProfile (name, favourite teams and leagues, weekly limit) and UserBet (one row per bet, unique per user and device id). Signing in merges anything saved on the device; every change is then synced, including SportyBet tickets from the extension. Signing out clears the device copy (for shared phones).
  • /account: sign in, create account, name, change password, delete account (password required; removes all saved data). Top-bar button shows the user's initial.
  • Admin → Users (staff only): totals; every user with joined date, last sign-in, bets, won/lost, staked and profit/loss (settled on the server with the same rules as the app); a user's bets; disable/enable; set a temporary password (there is no email service for resets yet). The admin sign-in now keeps the refresh token, so it no longer drops after 60 minutes (SEC-04).

Notes
